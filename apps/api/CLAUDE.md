# apps/api — api.legarec.fr (NestJS)

- Règles : `.claude/rules/api.md` (chargées automatiquement) ; référence : `docs/api.md` ; `docs/ia.md` pour le module `ai`. Lots : `PLAN.md`.
- `src/platform` : socle (configuration, base, accès, erreurs, journaux, files). `src/modules/<domaine>` : un module NestJS par domaine, nommé en anglais (glossaire de `CLAUDE.md`).
- Base : `Database.run(actor, fn)`, une transaction par requête avec les droits de son acteur ; Prisma, `pg`, BullMQ et ioredis interdits hors de `src/platform` (ESLint). Dans une route, `database.tx` ; seul `src/modules/auth` ouvre une transaction au nom d'un compte (ESLint).
- Comptes (`docs/api.md`, « Comptes ») : mots de passe, jetons, seconds facteurs et codes lus par `legarec_auth` seul, un compte à la fois ; jamais un lien, un jeton ou une adresse dans une table, une file ou un journal. Toute action sur le compte de quelqu'un d'autre passe par une fonction SQL qui revérifie qui agit.
- Chaque route : une règle d'accès (`@Staff`, `@StaffOrDelegate`, `@AnyStaff`, `@Partner`, `@Debtor`, `@Anonymous`, `@Public`, `@Hook`, `@ServiceAccount`), sans quoi l'API ne démarre pas ; un corps validé par `@Body({ schema })` avec un schéma de `packages/contracts/src/requests.ts` (jamais `@Req()`, `@Res()` ni `@Headers()`) ; `@Commits()` si elle engage ; `@OneTimeAnswer()` si elle montre une valeur une seule fois ; `Audit.log()` si elle est sensible (action de `src/platform/audit/actions.ts`, paramètres sans texte libre) ; une ligne dans `test/matrix.ts` et, pour une route reprise d'une simulation, dans `packages/contracts/test/*.parity.ts`.
- Tests HTTP : `startApp([], { sessions: true })` et `test/browser.ts` (vraies sessions), ou l'en-tête de test pour les droits ; `test/worker.ts` pour les e-mails ; `freezeClock()` quand un code d'application est tapé.
- Effet extérieur (envoi, appel d'un service) : `Outbox.add()` dans la transaction (`false` : clé déjà utilisée, rien de plus ne part), exécuté par le worker avec les droits de son auteur ; chaque tâche déclare de qui elle peut venir (`from`) et si elle peut être rejouée (`repeatable`), échoue par `GiveUp` ou `TryLater`, et n'agit avec les droits de l'application qu'après `authorize(mayActOn(dossier))`, avant tout envoi ; jamais d'appel externe dans une requête HTTP.
- Nouvelle table : migration SQL avec `app.secure()` ou `app.secure_case_table()`, droits par colonne, modèle Prisma ; jamais le moteur natif de Prisma (`migrate dev`, `db push`) ; une migration fusionnée ne se modifie plus ; les règles de `test/schema.test.ts` valent pour toutes les tables.
- Modèles d'e-mails : `templates/emails/` (copie de `kits/emails-handlebars` et `kits/emails-ajout-staff-message`, sans réécriture).
- Données de démonstration (seed) : reprendre les débiteurs, créanciers et montants de `maquette/donnees-demo/` (montants en centimes).
- Commandes : `pnpm services start|stop|status` (PostgreSQL et Valkey, sans root) ; `pnpm --filter @legarec/api dev|seed|account` ; `pnpm openapi` après un changement de route ; `pnpm verifier`. Jamais les ports 5432 et 6379 : ils sont pris par d'autres services de la machine.
